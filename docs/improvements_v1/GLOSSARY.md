# Glossary — AutoRFP Improvements v1

| Term | Definition |
|---|---|
| **Solution Plan / SoT (Source of Truth)** | The single, authoritative pre-plan document for an opportunity. Generated by the grilling + synthesis pipeline, editable by the user (TipTap), and injected into every gated document-generation prompt. Exactly **one per opportunity** (stable id). |
| **Grilling** | The interview phase: a Griller agent interrogates a Tech Lead agent across rounds, in two isolated AI sessions, relayed by the orchestrator. Minimum 2 rounds, default cap 4, hard cap 8. |
| **Griller** | Agent with solicitation (60k) + exec brief (8k, if it exists) context, no tools. Asks 1–3 pointed questions per round. Signals completion with the `INTERVIEW_COMPLETE` token. |
| **Tech Lead** | Agent with KB/RAG tools (`SOLUTION_PLAN_TOOLS`), a 10k opportunity primer instead of the raw solicitation. Answers with concrete decisions; never "it depends". |
| **Synthesizer** | Single AI call that turns the transcript + RFP + KB into the SoT HTML. Output targeted at ~10k chars of text so injection never truncates mid-section. |
| **Round** | One Griller turn + one Tech Lead turn, processed by one SQS worker invocation (step-per-round design). |
| **Run / `runId`** | One init-to-READY (or FAILED) execution of the pipeline. A fresh `runId` (ulid) is stamped on the plan at init and carried in every SQS message; workers no-op on mismatch (zombie-round protection). |
| **`INTERVIEW_COMPLETE`** | Literal termination token from the Griller. Honored only from round 2 onward and only when it is essentially the whole message (or the final line). Forced on the final round. |
| **Status (lifecycle)** | `GRILLING → GENERATING_SOT → READY \| FAILED`. Pure lifecycle — freshness is NOT a status. |
| **`isStale` / `staleReason`** | Orthogonal freshness flag, set by staleness triggers (exec-brief regen, solicitation upload) **only when status is READY** (no-op otherwise). Shows a warning banner; does not close the gate. |
| **READY** | Machine-complete state. Sufficient to pass the generation gate — no explicit human approval step in v1 (speed-first strategy). |
| **`version`** | Monotonically increasing counter on the plan, bumped by both regeneration and user saves. Never resets. S3 keys embed it (`.../v{version}/solution-plan.html`), so keys never collide. |
| **Gate** | Server-side check in `generate-document.ts`: gated doc types require a plan with status READY (isStale irrelevant). Returns `409 SOLUTION_PLAN_REQUIRED` otherwise. |
| **Gated doc types** | All RFP document types except `CLARIFYING_QUESTIONS`, `QUESTIONS_AND_ANSWERS`, `QUESTIONNAIRE`. |
| **Grandfathering** | If an opportunity already has ≥1 generated document of a gated type when gating turns on, the gate passes (with a nudge banner). New opportunities are fully gated. |
| **Escape hatches** | Env `SOLUTION_PLAN_GATING=off` (global) and org flag `enableSolutionPlan` (per-org; off = no gating, no UI section). |
| **SoT injection** | Loading the plan HTML in `processJobInner`, stripping to text, inserting as an `APPROVED SOLUTION PLAN (SOURCE OF TRUTH)` block with its own 12k-char budget (safety truncation logs a warning). |
| **`solutionPlanVersion` / `solutionPlanId` (on documents)** | Optional fields stamped on each generated RFP document recording which plan version it was built from. Enables future "built from outdated plan" detection. |
| **`search_service_pricing`** | Batched AI tool (`{services: [{serviceName, billingPeriod?}]}`, max 10) returning ALL third-party prices in one tool round. Never throws to the tool loop — failures degrade to "vendor quote required" rows. |
| **Pricing cache** | Global (cross-org) DynamoDB cache of public list prices. TTL 30 days for HIGH/MEDIUM confidence, **~24h for LOW** so bad lookups self-heal. |
| **Confidence (HIGH/MEDIUM/LOW)** | Haiku-extraction quality signal. LOW = search snippets did not state a price. |
| **Wipe-on-regenerate** | Re-init deletes the old transcript and overwrites the plan under the same id. Prior S3 versions and hand edits are not preserved (user is warned when `isUserEdited` is true). |
| **`isUserEdited` / `editedBy`** | Set when the user saves via the TipTap edit page (PATCH). PATCH is allowed **only when status is READY** (409 otherwise). |
